# Production accounts and financial instructions — implementation tranche

Baseline c99a636; branch `codex/native-solana-accounts-payouts`. Authorized local source/SBF/LiteSVM work only. No deployment. This implements production financial account/instruction code against the accepted economics. Candidate sealing, automatic Series B promotion, ORAO integration, round reopening, future configuration activation, account retirement/refunds, wallet/ICP integration and real Squads execution remain subsequent integration work. This tranche cannot operate the complete game by itself.

## Shared interfaces

One canonical pool: `[pool]`; separate admission pause `[admission]`; program-owned SOL custody `[game-vault]`; operations state `[ops]`; empty system-owned signer cash PDA `[ops-cash]`; singleton reusable allocation workspace `[ticket]`. User `[user, owner]`, UserRound `[user-round, round_le_u64, owner]`, retained Position `[position, owner, nonce_le_u64]`, Backer `[backer, series_u8, owner]`, dense global RegistryPage `[registry, page_le_u64]`, reusable SnapshotPage `[snapshot, page_le_u64]`. Page capacity **8**, slot/cursor/count widths **u64**, no economic population cap. All accounts bind canonical seeds and owner. Per-owner rent for User/UserRound/Position/A is owner paid; shared account/page storage is sponsor paid from OpsCash.

Cash partitions are u64; entitlements, lifetime credits and P/L are u128; weighted denominators use U256 (32-byte little-endian). GameVault spendable cash equals pot + seed + management + pending toll + funded claims + unallocated excess. Rent is protected. Incoming anonymous transfers increase excess, never game credit. Only recorded accrued management is withdrawable by its recipient; operations contributions are separate and nonrefundable. Owner destinations require the owner signature and reject protected custody aliases. Runtime fees are separate.

Allocation captures the **single** dense registry before senior credit. Slices are **35% senior / 45% proportional A / 20% equal B** of the Backer half, with accepted missing-tier folds. Six phases: Discover, Senior, SealWeights, Allocate, descending Prune, constant-size Commit. One-row instruction fallback is the initial measured ABI; larger batching/inline completion is an optimization to measure, not a population cap. Lifetime increases at credit; ticket-pending credit becomes claimable only at scalar watermark commit. Old finalized cash remains claimable during a new ticket. Claims never reduce lifetime entitlement consumption.

Shared registry/snapshot pages are permissionlessly provisioned **before** financial acceptance. A payout verifies all required snapshot pages already exist (using Pool.snapshot_pages), so accepted cash progress does not rely on later rent funding. This is the initial reusable-storage path. Automatic closing costs additionally lock a fixed configured provider/B reserve in operations accounting before a closing payout. No on-chain keeper reward. Default owner contribution is zero; optional per-payout owner rent fallback is not yet implemented and is explicitly deferred to resource integration. Provisioning and allocation do not require governance or the original caller. No cash-abort/reset escape hatch is provided.

Pool contains current round, financial partitions, global registry length/version, next first-funding sequence, next ticket/finalized ticket IDs, snapshot page count, participant count, closing time/deadline, governance and guardian vault identities, sponsor and management recipients, and configured close reserve. Ticket stores all captured allocation terms/cursors/totals/oldest row, 256-bit A denominator, cash credit sums and seed delta. Prune validates original row + current last row/backer and updates moved membership before shortening the live registry. Original snapshot pages remain immutable within a ticket.

Only strict `owed > pot` closes; equality remains active even at zero pot. Close pins Clock+600 once and disables new financial admission/position payouts. The closing marker preserves the later provider/candidate contract; this tranche intentionally has no premature reopening instruction. Admission pause touches only Admission and guardian signer. Cash claims/progress remain available while paused. Ordinary game opens remain allowed during a nonclosing allocation; A/registry mutation and further payouts are blocked until commit.

Governance G and guardian P are canonical Squads-v4 vault PDAs, authenticated by executable program/ProgramData upgrade-authority linkage at initialization. G: autonomous zero config authority, 2-of-3 voting membership and 172800-second delay; P: separate autonomous 2-of-3 voting membership and zero delay. Application authorization uses the Vault CPI signer, not member signatures on each application transaction. Local Squads profiles/CPI fixtures establish the application boundary only; actual Squads approval/execution and deployed readback are separate evidence.

## Implementation ownership and validation

State worker owns `state.rs`; controls worker owns `controls.rs`; position worker owns `positions.rs`; allocation worker owns `allocation.rs`. Coordinator owns shared lib/manifests/locks/math/custody helpers, one build executor, evidence, documentation and graph. Runtime worker owns the financial harness. No parallel Cargo builds. Meaningful failing financial assertions precede completed handlers, followed by actual compiled SBF transactions, exact expected rejection/fee-only rollback, cash conservation, host golden vectors, quotas/nonces/owner checks, cap/prune/claim separation and packet/CU measurements. Independent reviews follow deterministic checks.
